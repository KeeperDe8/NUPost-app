4. CRITICAL TECHNICAL GOTCHAS & APPLIED SOLUTIONS
================================================================================

1. TIMEZONE SYNCHRONIZATION (Asia/Manila / UTC+8):
   - Issue: The MySQL database stores timestamps in UTC without a 'Z' or timezone
     offset. Previously, dates displayed 8 hours behind, and notifications showed
     "8 hours ago" right after submitting.
   - Solution: Centralized in lib/utils/app_date_time_utils.dart.
     Always use AppDateTimeUtils.parseServerDateTime(rawString) which detects
     UTC and converts to device local time (.toLocal()).
     Displayed submission format: 'Submitted YYYY-MM-DD HH:mm:ss' (Philippine Time).

2. NOTIFICATION TAP DEBOUNCE & OPTIMISTIC UI:
   - Issue: Rapid double/triple tapping a notification card caused slow loading
     and opened duplicate screen instances.
   - Solution: In lib/screens/notifications_screen.dart:
     * Added '_isNavigating' guard to reject rapid duplicate taps.
     * Implemented 0ms optimistic UI: notifications mark as read in local state
       instantly, while API sync runs in the background with Future.wait.
     * Styled the unread indicator as a centered vertical pill (width: 4, height: 56)
       matching the Home Screen design.

3. HOSTINGER MEDIA & IMAGE UPLOAD PIPELINE:
   - Issue: Hostinger separates public_html and the Laravel app root. Images
     uploaded from mobile could 404 or throw ImageCodecException in Flutter.
   - Solution:
     * In LegacyMobileApiController.php (createRequest / updateRequest), uploads
       are written to public_path('uploads') and mirrored to
       base_path('../public_html/uploads').
     * Camera .jfif files are automatically normalized to .jpg on upload.
     * Direct media endpoint: https://nupost.site/api/media.php?file=<filename>
       searches public_html/uploads, public/uploads, and storage/app/public/uploads.
     * If a file is missing, media.php returns a 1x1 transparent PNG fallback
       so Flutter's Image.network never crashes.

4. RE-SUBMISSION & REJECTION WORKFLOW:
   - Admins can reject requests with an admin_feedback note.
   - In RequestTrackingScreen, requestors see an Admin Rejection Reason card and
     a "Re-Submit Request" button.
   - Tapping it loads CreateRequestScreen in edit mode (isEdit: true), allowing
     the user to update text/media and reset the status back to 'Pending' review.

6. BRIEF FOR WEB REPOSITORY AGENT (Nielqttt/nupost) - SLA SORTING & URGENCY
================================================================================
Target Repository: https://github.com/Nielqttt/nupost.git (Branch: main)
Target File: app/Http/Controllers/Api/LegacyMobileApiController.php

OBJECTIVE:
Update the adminRequests endpoint in LegacyMobileApiController.php so that it
automatically calculates SLA slack days and sorts the admin queue by urgency.

1. SLA LEAD TIMES BY CATEGORY:
   - 'Event Documentation'                  -> 30 days
   - 'New Campaign / Creative Concept'     -> 10 days
   - 'Multiple Collaterals / Tarpaulins'    -> 5 days
   - 'Standard PubMat'                      -> 3 days
   - 'Template-Based PubMat'                -> 2 days
   - Default / General                      -> 1 day

2. SLACK & URGENCY FORMULA (PHP / Carbon):
   $category = (string) ($r->category ?? 'General');
   $slaDays = match($category) {
       'Event Documentation' => 30,
       'New Campaign / Creative Concept' => 10,
       'Multiple Collaterals / Tarpaulins' => 5,
       'Standard PubMat' => 3,
       'Template-Based PubMat' => 2,
       default => 1,
   };

   $prefDate = $r->preferred_date ? \Carbon\Carbon::parse($r->preferred_date)->startOfDay() : now()->addDays(3);
   $latestStart = $prefDate->copy()->subDays($slaDays);
   $today = now()->startOfDay();
   $slackDays = (int) $today->diffInDays($latestStart, false); // negative = overdue

   $isAtRisk = $slackDays < 0;
   $isDueSoon = $slackDays >= 0 && $slackDays <= 1;

   $prioStr = strtolower(trim((string) ($r->priority ?? 'Low')));
   $prioWeight = match($prioStr) {
       'urgent' => 0,
       'high' => 1,
       'medium' => 2,
       default => 3,
   };

3. RETURN FIELDS IN MAPPED ARRAY:
   'slack_days'   => $slackDays,
   'is_at_risk'   => $isAtRisk,
   'is_due_soon'  => $isDueSoon,
   '_prio_weight' => $prioWeight,

4. SORTING LOGIC:
   ->sort(function ($a, $b) {
       if ($a['slack_days'] !== $b['slack_days']) {
           return $a['slack_days'] <=> $b['slack_days'];
       }
       if ($a['_prio_weight'] !== $b['_prio_weight']) {
           return $a['_prio_weight'] <=> $b['_prio_weight'];
       }
       return strcmp($b['created_at'], $a['created_at']);
   })
   ->values();

5. DEPLOYMENT:
   Once committed and pushed to 'main' on Nielqttt/nupost, GitHub Actions
   automatically deploys the updated controller to https://nupost.site via SSH.

7. 24-HOUR EXACT DUPLICATE HASH CHECK PROTECTION
================================================================================
Status: Deployed to Nielqttt/nupost (main) and KeeperDe8/NUPost-app (main)
Controllers:
- Mobile API: app/Http/Controllers/Api/LegacyMobileApiController.php (createRequest)
- Web Requestor: app/Http/Controllers/Requestor/RequestController.php (store)

OBJECTIVE:
Prevent accidental double submissions and spamming of identical requests
within a 24-hour window.

LOGIC:
1. Normalize and compute MD5 hash of title and description:
   $contentHash = md5(strtolower(trim($title)) . '|' . strtolower(trim($description)));

2. Query recent non-rejected requests within last 24 hours:
   $recentDuplicates = DB::table('post_requests')
       ->where('status', '!=', 'Rejected')
       ->where('created_at', '>=', now()->subHours(24))
       ->get();

3. Abort on exact match with HTTP 422 (or back with error on web):
   "Duplicate submission detected. An identical request was submitted within the last 24 hours."

4. No quotas or AI spam checks are enforced—only exact duplicate blocking.
